# PC bridge contract (remote protocol unchanged at 1.2)

Canonical remote contracts: `001-remote-development/contracts/protocol.md`, `002-mobile-workflows/contracts/protocol.md`, `003-task-centered-experience/contracts/protocol.md`. PC package mirrors must be traceable; do not import iOS source or copy the server/adapter.

Local methods live in the existing authenticated owner `remoteDev` Typert namespace, with no model tool exposure or independent listener. Names are prefixed `pc` and use serializable request/result types. Implementation may group profile operations, but observable behavior is fixed here.

- Pair preview parses only the exact 002 link, bounded 8 KiB, strict URL/expiry/network rules; returns redacted summary and a short-lived opaque local confirmation handle. No exchange or socket until explicit confirm. Confirm consumes this handle, exchanges once with no redirects, checks endpoint/host, stores the device token privately, and verifies host.info before reporting connected.
- Profiles list exposes id, endpoint, verified host id/name, device metadata and connection status; never token/secret. Reconnect reads credential locally. Forget removes only that profile and its bridge connection; revoke-self forwards the existing authenticated method and then forgets. Reject symbolic-link or permissive storage paths rather than writing credentials outside the private plugin directory.
- Connect returns `{profileId, hostId, generation, hostInfoJson}`. Generation is unique per connection (including reconnect). No request may select an arbitrary endpoint/token from a browser payload. An in-flight request captures socket and generation. Validate expected generation immediately before send; connection changes reject pending calls.
- RPC forwarding takes `{profileId,generation,method,paramsJson}` and returns `{resultJson}` or a structured failure preserving numeric remote code and bounded data. Only 001–003 developer methods are allowed; management/pair issue/arbitrary URLs/internal local Remote methods are denied. Request/response frames are bounded to 28 MiB (29,360,128 UTF-8 bytes), matching canonical protocol v1; the maximum 20 MiB image payload encodes to 27,962,028 base64 bytes and leaves 1,398,100 bytes for JSON-RPC envelope/metadata. Decoded image payloads remain capped at 20 MiB. WebSocket follows no redirects and validates normal TLS trust. Credentials are in `Authorization` only, never URL/subprotocol/log/error.
- The native session adapter uses the existing DSH Remote stream or bounded polling backed by real `session.read`/`session.subscribe` replay. Sequence and retentionFloor are authoritative. Polling must not synthesize events/status; client applies `(sessionId,sequence)` deduplication and native replacement projection, retains unknown events, reports an expired cursor and recovers via a fresh read.
- In the native adapter, non-idempotent worktree/session create failures with unknown transport outcome enter durable uncertain state and are not auto-retried. Known successful IDs persist. Prompt retry uses original clientMessageId; accepted receipt is not completed execution. Review metadata carries exact workspace/review/snapshot identity and is revalidated both before draft append and eventual send.
- The connection-only plugin does not own task drafts or a parallel timeline. Existing old browser draft keys remain untouched. The native adapter uses native DSH draft/lifecycle ownership with host-qualified identities, never credentials or pairing links in drafts.

Legacy `openTunnel` and `openProject` must stop returning credential URLs or scraping DSH logs and return a migration error directing to pairing; already running legacy tunnel close/list and unrelated SSH/rd-core methods remain available under explicit legacy labeling. Existing settings are preserved. The PC primary UI does not register the old directory-picker shadows or offer legacy batch mutation as code review.

## Revision B native DSH boundary

The browser-facing local bridge remains an implementation adapter. The native DSH session/composer contracts, discovered from the actual installed runtime, own UI state and presentation. A native remote binding maps namespaced local presentation IDs to `{profileId,hostId,generation,workspaceId,sessionId}` and preserves the exact remote protocol. Converting event envelopes must preserve the native sequence/type/payload already carried by Perse, without inventing execution or approval events. Native actions without a compatible supported remote operation fail explicitly; they must never fall through to a local model, shell or workspace because the selected item is remote.

Connection configuration is the only plugin main page; necessary sidebar navigation may select the native remote binding. The earlier independent PC draft/timeline/project-tools/review UI is retired. The approved backend interface below fixes the native integration boundary.

## Approved native backend registration

The DSH client `ISessions` gains an observable `externalCatalog`, `registerExternalBackend(backend)`, `createExternalSession(address, options)`, and an external address overload of the existing retain/open lifecycle. An external address contains `{backendId, workspaceId, sessionId}`; remote project paths never become local `WorkspaceId` or filesystem authority. Backends have verified `{backendId, hostId, hostName, generation}`, a catalog observable, and refresh/create/open operations. Opening provides the native `SessionFace`, `SessionEventSource`, and exact disposal callback. DSH owns namespaced presentation identities, scoped bindings, reference counting, and invalidation; Perse owns canonical wire conversion and authenticated bridge calls. Registration is scoped and removable. An absent extension leaves connection configuration usable with an explicit compatibility notice.

The native workspace sidebar consumes the separate external catalog as host → project → session groups. Selection calls normal native session navigation; new remote sessions are created against an explicit authorized project and opened only after a confirmed ID. Local workspace rows, creation, and models retain their current behavior. Remote mutations with an unknown outcome are not retried automatically. A disconnected or replaced generation rejects stale callbacks and actions; reconnect may recover the same logical session without re-executing prompts.

Native components that call local APIs outside the SessionFace must be audited. Unsupported remote model/settings, local file uploads, workspace menus, search, fork, export, or permission controls must be unavailable with an explanation, or routed through an explicit supported backend operation. Namespaced presentation IDs must never be dispatched to local execution APIs. Normal native conversation rendering, draft ownership and prompt submission remain authoritative. No custom remote chat renderer is introduced.

Native backend bindings expose separate observables for canonical gateway envelopes and pending approvals. Gateway `sequence` is never substituted for `payload.nativeSequence`: native events retain the native sequence and replacement metadata; gateway-only status, errors and approvals update their own state. Unknown native event types remain lossless client-only opaque records, without becoming model-visible journal events or assistant messages.

Perse already publishes durable approval request envelopes with `{approvalId,title,detail,choices}` and resolution envelopes with `{approvalId,resolved:true,decision,outcome}`. Fold unresolved requests into the binding approval source and reuse the native approval panel. `respondExternalApproval` validates the retained backend object, generation, session, pending ID and advertised one-shot choice, then dispatches existing `approval.respond`. Only `allowOnce` and `deny` are available; no remembered permission or local approval fallback. Late responses cannot settle a replacement binding.

Capabilities distinguish queued prompt submission from queue edit/remove. The current adapter supports text prompt, interrupt, history, title, durable attachment read and one-shot approvals where the host advertises them. Steer, queue edit, file upload through local FileUploadRuntime, local model/preset/permission changes, user-question answers, local terminal and local slash commands are unavailable until explicitly routed. Unsupported controls explain their limitation. Reading or navigating a remote session must work without a configured local model or API key.

Concurrent native create calls for the same backend, verified host, exact generation and workspace share one pending operation, including catalog reconciliation. The first caller’s options apply. Settle removes the in-flight entry; a later explicit create is a new request. An uncertain creation receipt is persisted before dispatch but is not shown as unresolved while that live request is pending. Acknowledging an uncertain receipt only clears local metadata, never retries or associates a guessed remote session.

The native main-conversation scope must observe retained external bindings as well as local catalog sessions. A selected external sidebar row is not completion: the session-maybe/native composer scope must receive that exact binding. This uses a controller-owned observable of retained native bindings/identities with source counts, updated on retain/release and generation retirement; remote paths remain outside the local workspace catalog.
