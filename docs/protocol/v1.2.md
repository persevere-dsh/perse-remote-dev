# Additive protocol and local workflow contract

All v1/v1.1 methods remain compatible. The host reports `protocolVersion: "1.2"` and optional host capability `gitBranches` when the read method below is available. Old clients accept the same major. No create/send mutation gains implicit retry semantics.

## Local branch enumeration (T02)

`git.branches({workspaceId})` returns:

```json
{"current":"main","branches":[{"name":"main","head":"0123456789012345678901234567890123456789","current":true}],"truncated":false}
```

Read only local `refs/heads`; no fetch, checkout, hooks, external diff drivers or network activity. Resolve the workspace with the existing canonical allowlist/worktree resolver. Return at most 1000 branches and mark truncation. Detached HEAD yields `current: null`; an unborn repository may return its symbolic current branch with an empty list. `head` is the resolved object hash. Reject unauthorized workspaces before starting Git; structured errors follow 001. Clients without this capability retain an explicitly entered base ref/HEAD and explain that branch listing is unavailable. No invented branch list.

## Task submission (T03/T04)

Capture immutable `{profileId, endpoint, hostId, sourceWorkspaceId, provider, model?, reasoningEffort?, target, baseRef, text, clientMessageId}` at explicit send. Validate against current capabilities/authorized workspaces. In local mode use the selected workspace. In worktree mode use `worktree.create` with a label derived from the prompt; display the host-returned workspace/branch. Then create the session and send the captured prompt.

Known stage success is retained; a transport error during worktree/session creation is an uncertain outcome, never evidence that nothing was created. Resume only a known next stage or inspect/refetch before the user's explicit new attempt. Never blindly repeat those two mutations. `session.prompt` retries reuse its original clientMessageId; a receipt is acceptance, not completed execution. Connection/profile/workspace changes invalidate stale continuations. No automatic cleanup or force removal.

## Client state (T01/T05/T08)

New task home/editor share one draft/configuration. Existing task state is keyed by stable configured profile, endpoint, verified host and session. Review editor state adds review ID/snapshot hash and exact old/new line anchor. In-flight request guards additionally use connection generation. Context changes do not mutate an existing session's identity.

The RPC actor validates an expected socket generation immediately before actual dispatch, in addition to UI/AppModel guards before/after awaits. A request queued for an old connection must fail locally rather than be sent through a newly connected host. This is a client safety rule, not a new wire parameter.

`review.prompt` remains construction only. Its text and `{workspaceId, reviewId, snapshotHash}` are attached to the original task draft with a deduplication key. Before eventual explicit send, revalidate the stored snapshot using existing review APIs; if stale, retain the draft and explain refresh/review. Do not silently map old comments to new lines. Existing standalone review history/deletion continues to obey 002, including removed workspaces.

Pins are local metadata, not a new server field. Multi-host home aggregates only previously read real metadata; cached rows must be visibly distinct from current authenticated data. Opening a cached task first authenticates and validates its host/workspace.
