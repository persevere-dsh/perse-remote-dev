# Remote protocol v1

Transport: authenticated WebSocket endpoint `/rpc`. Each text frame is JSON-RPC 2.0 (`jsonrpc: "2.0"`), client request numeric/string `id`; response contains `result` or `{code,message,data?}` error. Handshake uses `Authorization: Bearer <token>`. `GET /health` returns only health/protocol version, no workspace/session details. No tokens in URLs. Default port 8787, loopback bind. Non-loopback requires configured TLS or explicitly acknowledged private-network mode, documented as such.

Each UTF-8 WebSocket frame is limited to 28 MiB (29,360,128 bytes) in either direction. This leaves 1,398,100 bytes of JSON-RPC envelope and metadata budget for a 20 MiB image encoded as canonical base64 (27,962,028 bytes maximum). The decoded prompt attachment payload is limited to 20 MiB total per request; encoded data must be canonical base64. The frame limit is transport capacity, not an increase to the image payload limit.

The gateway requires an explicit host-side `workspaceIds` allowlist. An empty list exposes no workspaces; registering a project in DSH alone does not authorize this gateway to expose it. Workspace checks precede session creation and any other mutation.

If a native subscription fails without an intentional unsubscribe/abort, the gateway appends a durable `error` event followed by `status` with `payload.status: "error"`, and broadcasts both as `session.event`. It also sends `session.error` with params `{sessionId,message}` for immediate stream-failure reporting. Clients must present this notification and allow recovery; a WebSocket remaining open does not imply that its native subscription is healthy. Later native status events supersede the failure state.

All paths are relative to a configured `workspaceId`. Provider IDs: `dsh` and optional `codex`. All dates are ISO 8601 UTC. Fields below are exact lowerCamelCase. Extra fields can be ignored. Optional missing functionality returns error `-32004` with a reason; it must not return a placeholder success. Permission/auth `-32001`, not found `-32002`, conflict `-32009`, invalid params `-32602`.

Every response error `code` is an integer. Native DSH string error codes are mapped to the appropriate numeric gateway code, or `-32603` for an unmapped internal error, and may be preserved as `data.nativeCode`. A blank session cannot be forked until DSH has a completed turn; this returns a conflict with `data.nativeCode: "session/fork-unavailable"`.

## Models

- Workspace: `{id,name,path}` (path informational only).
- Session: `{id,workspaceId,provider,title,status,createdAt,updatedAt,archived,model?}`. Status: `idle|running|waitingApproval|error|interrupted`.
- Event: `{sessionId,sequence,type,timestamp,payload}`. Sequence is monotonically increasing per session. Types: `userMessage|assistantDelta|assistantMessage|thinking|tool|status|approval|error|terminal|notice`. Payload is an object; text-bearing events use `text`; status uses `status`; approvals use `approvalId,title,detail,choices`; terminal uses `processId,text,exitCode?`. An assistantMessage is a committed message and must replace/deduplicate its streaming fragment using payload `messageId` where supplied.
- `sequence` belongs to the persistent gateway journal, not the upstream native DSH log. Native durable events include `payload.nativeSequence`; source IDs prevent importing them twice. Native `payload.surfaceOp: {op:"replace",startSeq,endSeq}` refers to **native** sequence numbers and replaces visible source events in that inclusive range. Preserve raw ledger/replay history; apply replacement only when projecting the conversation for display. `payload.sourceEventSeqs` carries native source references. Live assistant fragments share `messageId`; distinct sequence numbers with that same ID are not duplicates. A final committed message replaces its matching streaming fragments.
- Every `session.event` notification has the Event directly as `params`, without an additional `{event:...}` wrapper. Approval requests and resolutions are journal events too. Requests carry `approvalId,title,detail,choices`; every terminal resolution carries the same `approvalId`, `resolved:true`, `decision` (`allowOnce|deny|timeout|cancelled|shutdown`), and the DSH `outcome` (`allowed-once|rejected|cancelled|unavailable`). Each pending request emits exactly one terminal resolution. Historical native approval audit records must not render as actionable pending requests.
- Provider: `{id,name,available,reason?,capabilities:[string],models:[{id,name,reasoningEfforts?:[string]}]}`.
- Durable image references use `{attachmentId,mediaType,bytes,width,height,name?,originalDimensions?}`. A native message may expose these under `payload.message.content[]` as `{type:"image",attachment:ImageAttachmentRef}`. Clients show a preview only after resolving this session-owned reference through `session.attachment`; an opaque reference is never treated as a URL or local path. Image bytes are limited to 20 MiB; `session.attachment` base64 data is limited to 27,962,028 UTF-8 bytes and its containing WebSocket frame to 28 MiB.
- Capability names: `sessions`, `prompt`, `queue`, `steer`, `interrupt`, `approvals`, `fork`, `files`, `fileWrite`, `git`, `gitWrite`, `terminal`, `tools`, `skills`, `attachments`. `queue` means a follow-up is enqueued while the current run continues; `steer` means the provider can redirect an active run. The DSH rc2 adapter advertises `queue`, not `steer`. Native provider limitations must be reported.

## Methods

| Method | Params | Result |
|---|---|---|
| `host.info` | `{}` | `{protocolVersion:"1.0",host:{id,name,platform},capabilities:[string],providers:[Provider],workspaces:[Workspace]}` |
| `workspace.list` | `{}` | `{workspaces:[Workspace]}` |
| `session.list` | `{workspaceId?,provider?,archived?:false,query?,cursor?}` | `{sessions:[Session],nextCursor:null|string}` |
| `session.create` | `{workspaceId,provider,title?,model?,reasoningEffort?}` | `{session:Session}` |
| `session.read` | `{sessionId,afterSequence?:0}` | `{session:Session,events:[Event],retentionFloor:number}` |
| `session.subscribe` | `{sessionId,afterSequence?:0}` | `{events:[Event],retentionFloor:number}`; subsequent events via `session.event` notification |
| `session.prompt` | `{sessionId,text,clientMessageId,attachments?:[{mimeType,data,name?}]}` | `{messageId:string,accepted:true}` (receipt, not turn completion) |
| `session.attachment` | `{sessionId,attachmentId}` | `{attachment:ImageAttachmentRef,data:string}` (base64 bytes; session ownership is verified by the host) |
| `session.interrupt` | `{sessionId}` | `{}` |
| `session.rename` | `{sessionId,title}` | `{session:Session}` |
| `session.archive` | `{sessionId,archived:boolean}` | `{session:Session}` |
| `session.fork` | `{sessionId,title?}` | `{session:Session}` |
| `approval.respond` | `{sessionId,approvalId,decision:"allowOnce"|"deny",answers?:object}` | `{}` |
| `file.list` | `{workspaceId,path?:""}` | `{entries:[{name,path,isDirectory,size?}]}` |
| `file.read` | `{workspaceId,path}` | `{path,content,sha256}` |
| `file.write` | `{workspaceId,path,content,expectedSha256}` | `{path,sha256}` |
| `git.status` | `{workspaceId}` | `{branch,entries:[{path,index,worktree}]}` |
| `git.diff` | `{workspaceId,path?,staged?:false}` | `{diff:string}` |
| `git.stage` / `git.unstage` | `{workspaceId,paths:[string]}` | `{}` |
| `git.commit` | `{workspaceId,message}` | `{commit:string}` |
| `terminal.start` | `{workspaceId,command}` | `{processId:string}` |
| `terminal.read` | `{processId,offset?:0}` | `{text,nextOffset,running,exitCode:null|number}` |
| `terminal.stop` | `{processId}` | `{}` |
| `tools.list` | `{provider,workspaceId}` | `{tools:[{id,name,description?}]}` |
| `skills.list` | `{workspaceId,sessionId?}` | `{skills:[{id,name,description,source,whenToUse?,modelInvocable}]}` |

`skills.list` returns native, user-invocable skill summaries. With `sessionId`, the host verifies that the session belongs to the selected allowed workspace and delegates to DSH's cold-read session skill catalog; `source:"session"` identifies the session-composition view. Without `sessionId`, the host reads the selected workspace under the DSH default agent-preset standing scope, without creating a session, Agent, or turn; `source` is the native skill source classification. `id` is the stable skill name and `modelInvocable` reports the host policy. The response never includes skill bodies, filesystem paths, provider locators, or arbitrary metadata. If the native skill registry is unavailable, the host omits the `skills` capability and returns `-32004` rather than a placeholder list.

Terminal is an explicitly submitted user command. Output may be polled; active client lifecycle must not terminate the host agent. Unknown JSON-RPC methods return `-32601`. Request timeout on the app is bounded; reconnect only retries reads/subscriptions automatically. Mutations are never blindly resent; prompts reuse `clientMessageId` and the gateway durably deduplicates.

## Connection/replay rules

1. Authenticate during WebSocket upgrade, then request host.info and check major protocol version.
2. Load sessions and session.read, subscribe from last received sequence. `retentionFloor` is the earliest sequence still available (or `lastSequence + 1` when the journal is empty); clients may detect an expired cursor when `afterSequence + 1 < retentionFloor`. Gateway must avoid a replay/live event gap; client deduplicates by `(sessionId,sequence)`.
3. On disconnect reject pending RPC requests, show offline status, reconnect with bounded exponential delay. Do not erase visible history or resend prompts automatically.
4. On host/provider failure persist and emit a useful error and terminal status. Interrupted work must never remain permanently running after restart.
5. Unknown event types render as a generic event, not a crash. Invalid data receives structured errors.
