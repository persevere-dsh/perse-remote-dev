# v1.1 additive contract

`protocolVersion` becomes `1.1`; v1 clients accept the same major. Existing methods stay compatible. Capabilities add `pairing`, `devices`, `worktrees`, `review`. New methods return explicit -32004 if unavailable. Dates are UTC ISO strings; hashes lowercase SHA-256 hex. Mutation errors follow v1 (-32001 authorization, -32002 missing, -32009 stale/conflict, -32602 invalid).

## Pairing and network

QR/deep-link encoding: `persevere://pair#<base64url UTF-8 JSON>`; payload exactly `{v:1,hostId,hostName,endpoint,pairingId,secret,expiresAt,networkMode}`. `networkMode` is `https|tailnet|local`. Secret is 32 cryptographic random bytes, encoded base64url; expires in at most 5 minutes; at most one successful exchange. JSON max 8 KiB. Payload is not trusted host identity until verified by exchange and host.info. It never contains master or durable device tokens. The phone must display and require confirmation before any network call.

Endpoint is canonical `wss://host[:port]/rpc`, with no credentials/query/fragment; `ws://127.0.0.1[:port]/rpc` (also localhost/::1) is permitted only for local simulator/testing flow and marked local. HTTPS reverse proxies serve the root paths intact. Release mobile pairing does not allow cleartext remote addresses. No trust-all certificate callbacks. HTTP exchange and RPC refuse redirects; HTTP redirects cannot forward secrets.

`POST /pair/exchange`, JSON max 16 KiB, body `{pairingId,secret,deviceName}` (name 1–100 chars), returns `{device:{id,name,createdAt},token,host:{id,name},endpoint,protocolVersion:"1.1"}` with `Cache-Control: no-store`. Token is 32+ random bytes returned only once, persisted as a hash by host, stored only in Keychain on mobile. Unknown/expired/consumed secret returns HTTP 401 with generic `{error:{code:-32001,message:"配对码已失效，请在主机重新生成"}}`; invalid JSON 400; bounded rate limit 429. No permissive CORS, no token in query, logs or error bodies. Endpoint/host ID must equal confirmed payload before saving a profile. A lost exchange response requires a new pairing; do not return token again on retry.

Host management operates on a separate loopback port (default 8788), never forwarded by the deployment helper. It can issue/revoke pairing, list/revoke devices and show configured network diagnostics. Exact admin HTTP/CLI layout is implementation-owned and documented in plugin README. Master Bearer authenticates CLI; the web page must not embed master in HTML. It exchanges a local one-time page ticket for an HttpOnly strict SameSite session and uses CSRF+Origin/Host checks for mutation. Device Bearer must fail every management method. Persist device hashes/metadata; revoke terminates its sockets immediately. Outstanding pairing tickets may be memory-only and expire on restart; device grants may not.

Authenticated mobile RPC additions:

| Method | Params | Result |
|---|---|---|
| `connection.info` | `{}` | `{hostId,endpoint?,networkMode:"https"|"tailnet"|"local",device?:{id,name,createdAt},checks:[{id,status:"ok"|"warning"|"error",message}]}` |
| `device.revokeSelf` | `{}` | `{revoked:true}` followed by connection close; master connection returns -32004 |

`connection.info` describes host configuration, not a claim about reachability from the phone. The phone separately checks health and authenticated host.info with bounded timeouts, maps DNS/TLS/refused/timeout/401 to useful messages. Host checks do not accept arbitrary probe URLs. Public endpoint configuration never changes bind or starts a tunnel implicitly.

## Managed worktrees

Workspace extends v1 optionally with `{kind:"repository"|"worktree",parentWorkspaceId?,branch?}`. Worktree: `{id,workspaceId,parentWorkspaceId,name,path,branch,head,baseCommit,createdAt,dirty,locked,removable,blockedReasons:["dirty"|"locked"|"sessions"|"terminal"]}`. Path is display-only. IDs and branch names generated by host; `name` is a label, not a filesystem path or raw Git branch. Branch format `perse/<slug>-<short-id>`. Creation under host-owned 0700 managed root (configurable); no client path. `baseRef` resolves to a local commit before Git invocation; no fetch/pull or network side effects.

| Method | Params | Result |
|---|---|---|
| `worktree.list` | `{workspaceId}` (root or child) | `{worktrees:[Worktree]}` |
| `worktree.create` | `{workspaceId,name,baseRef?:"HEAD"}` | `{worktree:Worktree,workspace:Workspace}` |
| `worktree.remove` | `{workspaceId,worktreeId}` | `{removed:true,worktreeId}` |

Remove refuses untracked/modified files, locked worktree, active agent/terminal, **any non-archived session**, missing/mismatched ownership, or an unowned/external worktree. No force, recursive delete fallback, branch deletion or hidden session archive. Git remove cleans only verified owned worktree; retain its branch. Creation serialized per root; failure rolls back only objects proven created by that operation. Metadata persists and reload validates root authorization and canonical repo identity. Child IDs are exposed consistently in workspace.list, host.info, session, file, Git, terminal and skills.

## Review

Scope: `working` (HEAD to working tree including untracked), `staged` (HEAD to index), `unstaged` (index to working tree including untracked), `branch` (merge-base of selected baseRef and HEAD to HEAD). Reject an invalid/no-common-ancestor base with an actionable error. No mutation of branch/index to compute diff.

`ReviewLine`: `{kind:"context"|"add"|"delete",text,oldLine?:number,newLine?:number,oldAnchor?:ReviewAnchor,newAnchor?:ReviewAnchor}`.
`ReviewAnchor`: `{path,side:"old"|"new",line:number,contextHash}`; contextHash supplied by host for the exact line; only returned anchors can be commented on.
`ReviewHunk`: `{oldStart,oldCount,newStart,newCount,header,lines:[ReviewLine]}`.
`ReviewFile`: `{path,oldPath?,status,additions,deletions,binary,truncated,hunks:[ReviewHunk]}`.
`ReviewComment`: `{id,anchor:ReviewAnchor,body,createdAt}`; body 1–4000 chars.
`ReviewSnapshot`: `{id,workspaceId,scope,baseRef?,baseCommit,headCommit,snapshotHash,createdAt,files:[ReviewFile],comments:[ReviewComment],viewedPaths:[string],stale:boolean,truncated:boolean,warnings:[string]}`.

Hash covers workspace/repository identity, scope/base/head, complete underlying change identity (including index and untracked bytes) and parsed snapshot version. Binary/omitted data must affect staleness. Limit patch/content to bounded bytes/file counts; show per-file binary/truncated markers and warnings. Disallow external Git diff drivers/textconv. No arbitrary path reads; reject symlink escape and special files. File names containing spaces/quotes/newlines must be parsed using Git's documented quoting/NUL formats and displayed safely.

| Method | Params | Result |
|---|---|---|
| `review.diff` | `{workspaceId,scope,baseRef?}` | `{review:ReviewSnapshot}`; same exact current snapshot reuses ID/comments/viewed state |
| `review.list` | `{workspaceId}` | `{reviews:[{id,workspaceId,workspaceName,workspaceRemoved,scope,baseRef?,snapshotHash,createdAt,commentCount}]}`; recent max 50; a root query also includes its owned children, including removed children; a child query returns that child only |
| `review.read` | `{workspaceId,reviewId}` | `{review:ReviewSnapshot}`; historical diff retained, stale recomputed |
| `review.delete` | `{workspaceId,reviewId,snapshotHash}` | `{removed:true}`; explicitly delete this stored snapshot and its comments after UI confirmation; validate supplied hash against stored snapshot, allow deleting stale history |
| `review.comment.add` | `{workspaceId,reviewId,snapshotHash,anchor:ReviewAnchor,body}` | `{comment:ReviewComment}` |
| `review.comment.remove` | `{workspaceId,reviewId,snapshotHash,commentId}` | `{removed:true}` |
| `review.viewed.set` | `{workspaceId,reviewId,snapshotHash,path,viewed:boolean}` | `{viewedPaths:[string]}` |
| `review.prompt` | `{workspaceId,reviewId,snapshotHash}` | `{workspaceId,snapshotHash,text}`; **construct only**, never starts a session/turn |

Comment/viewed mutations and prompt validate current snapshot and workspace ownership; stale returns -32009 with `{currentSnapshotHash,reason:"review_stale"}`. History deletion validates ownership and stored hash, but does not require the old code to still be current. Comments are literal user content, not commands. Prompt is Chinese and contains each comment with JSON-quoted path, side/line/context hash, and the exact corresponding source line (bounded to 500 characters and JSON-quoted); it asks the agent to inspect first, make focused repairs, and not commit automatically. Mobile shows full prompt preview, selects or creates session in the same workspace, then submits through existing session.prompt only on confirmation. Reviewed-state metadata must not change snapshot hash. Persistence survives restart; history retention limits must be explicit rather than silent discard of active review comments. Enforce a total storage ceiling (32 MiB initial default); on limit, instruct the user to delete selected history through the actual review.delete UI/API, never silently evict reviews.

Worktree removal retains a minimal ownership tombstone while historical reviews exist. `review.read/delete` use each list item's workspaceId and authorize through the original parent's current allowlist. A removed child's `review.read` returns the saved immutable snapshot with `stale:true` without requiring its former cwd to exist. Such history is visible from the parent project and may be deleted; it must not grant file/session/terminal access to a removed directory. Removing parent authorization removes history access too. Mobile labels removed workspaces and uses each row's workspaceId for read/delete, not the currently selected parent ID.
